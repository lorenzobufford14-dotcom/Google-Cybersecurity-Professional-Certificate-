## 🛠️ Module Overview
This module explores the 8 CISSP Security Domains, risk management frameworks (NIST RMF), security audits, and the core tools used by analysts to establish and maintain an organization's **security posture**—its overall capability to defend critical assets and adapt to emerging threats.

---

## 🛡️ The 8 Security Domains Breakdown

### 1. Security and Risk Management
* **Focus:** Defining security goals, risk mitigation, compliance, business continuity, and legal/regulatory requirements (e.g., GDPR, HIPAA).
* **Key Concepts:**
  * **Risk Mitigation:** Implementing rules, policies, and technical controls to reduce the impact or likelihood of a breach.
  * **Business Continuity:** Establishing disaster recovery plans to maintain essential operational functions during a security incident.
* **Core InfoSec Processes:** Incident response, vulnerability management, application security, cloud security, and infrastructure security.

### 2. Asset Security
* **Focus:** Securing digital and physical assets across their entire lifecycle (storage, maintenance, retention, and destruction).
* **Key Practices:**
  * Managing sensitive data categories like **PII** (Personally Identifiable Information) and **SPII** (Sensitive PII).
  * Enforcing physical security policies, such as supervising physical hard drive destruction before disposal to prevent threat actors from recovering sensitive data.
  * Establishing regular data backup protocols to ensure rapid recovery following a security incident.

### 3. Security Architecture and Engineering
* **Focus:** Designing resilient security systems, optimizing data security controls, and engineering safe operational environments.
* **Key Principles:**
  * **Shared Responsibility Model:** Ensuring both cloud providers and organizations actively manage risk and security obligations.
  * **Core Design Concepts:** Least Privilege, Defense in Depth, Fail Securely, Separation of Duties, Keep It Simple, Zero Trust, and "Trust but Verify."

### 4. Communication and Network Security
* **Focus:** Securing physical networks, wireless communications, and remote connection channels.
* **Key Practices:**
  * Protecting remote employees connecting over public spaces, insecure Wi-Fi hotspots, or Bluetooth connections.
  * Enforcing secure access controls, encrypted communication tunnels, and restricted network segments.

### 5. Identity and Access Management (IAM)
* **Focus:** Managing identity authentication and authorization to control user access to critical systems and data.
* **Core Principles:**
  * **Principle of Least Privilege:** Granting users only the minimum access and permissions required to perform their specific job functions.
  * **Avoiding Shared Admin Accounts:** Enforcing individual credentials so all system activities can be audited and traced back to a specific user during an incident.
* **4 Pillars of IAM:**
  1. **Identification:** Asserting identity (e.g., username, access card, biometrics).
  2. **Authentication:** Verifying identity (e.g., password, PIN, MFA token).
  3. **Authorization:** Granting permission based on validated identity and role.
  4. **Accountability:** Logging and auditing user activity to track system usage.

### 6. Security Assessment and Testing
* **Focus:** Evaluating security controls, conducting security audits, testing vulnerabilities, and analyzing risks.
* **Key Practices:**
  * Performing regular vulnerability scans and penetration testing ("pen testing") to identify security gaps before attackers exploit them.
  * Auditing user permission levels and enforcing Multi-Factor Authentication (MFA) to validate control effectiveness.

### 7. Security Operations
* **Focus:** Investigating security incidents, monitoring threat activity, and executing defensive operational procedures.
* **Core Tools & Practices:**
  * Utilizing **SIEM** tools (Security Information and Event Management) for centralized log monitoring and alert analysis.
  * Executing **Playbooks** for standard incident response workflows, intrusion detection/prevention, log management, and digital forensics.
  * Performing post-incident reviews to capture lessons learned and improve future defense.

### 8. Software Development Security
* **Focus:** Incorporating security standards into the Software Development Lifecycle (SDLC).
* **Key Practices:**
  * Conducting secure design reviews during development phases and code analysis before deployment.
  * Verifying proper encryption configurations on specialized endpoint devices (e.g., healthcare devices storing private patient data).
